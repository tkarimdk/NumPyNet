# Lesson 05 — Multiclass classification

## Problem

A binary classifier predicts one of two classes. A multiclass classifier must choose between three or more mutually exclusive classes. In this version, a network predicts one of **three** synthetic spiral classes using two numerical coordinates as its input.

## Architecture

```
2 input coordinates -> Dense(2, 24) -> Tanh -> Dense(24, 3) -> logits
                                                         |
                                      fused softmax-cross-entropy loss
```

The final layer emits three *logits*, not probabilities. For reporting only, softmax converts those logits into class probabilities. Keeping logits until the loss calculation avoids taking `log(softmax(x))` on values that can underflow.

## The mathematics

For input logits \(z_1,\ldots,z_K\), softmax is

\[
p_k = \frac{e^{z_k-m}}{\sum_{j=1}^K e^{z_j-m}},\qquad m=\max_j z_j.
\]

The subtraction by \(m\) leaves the probabilities unchanged but prevents overflow from large positive logits.

For true class \(y\), categorical cross-entropy is

\[
L=-\log(p_y) = \log\left(\sum_j e^{z_j-m}\right)-(z_y-m).
\]

The class-logit derivative for a batch of \(N\) examples is

\[
\frac{\partial L}{\partial z_{ik}}=\frac{p_{ik}-\mathbb{1}(y_i=k)}{N}.
\]

We compute this gradient directly without multiplying an explicit softmax Jacobian by an unstable probability-based loss derivative. The separate `Softmax.backward()` method also implements the general Jacobian-vector product, for cases requiring a standalone layer.

ReLU, added in this release, returns `max(0, x)`. This project uses derivative 0 at exactly x = 0, a valid subgradient convention.

## Run it

```powershell
python -m numpynet check-multiclass-gradients
python -m numpynet train-multiclass --epochs 1200 --lr 0.7 --seed 7
```

The checker uses a deliberately small 2–4–3 network, comparing 27 analytical parameter derivatives with independently calculated central finite differences.

The experiment creates 100 training samples and 60 validation samples **per class** using separate random generators. Validation examples never contribute to parameter gradients. Training uses full-batch gradient descent. Metrics are recorded at initialization (epoch 0) and after each of 1,200 updates.

Files produced under `results/multiclass/`:

- `history.csv`: epoch, training loss/accuracy, validation loss/accuracy
- `loss_curves.svg`: browser-openable chart of both loss curves

## Exercises

1. Work out softmax for logits `[2, 1, 0]` and show that the probabilities sum to 1.
2. Calculate the derivative of cross-entropy with respect to all three logits when the true class is 1.
3. Increase `--noise` from `0.18` to `0.4`. Compare training and validation performance. Explain how class overlap changes the problem.
4. Change `--width` from `24` to `4`, keeping the same seed, and evaluate the effect on the model.
5. Run `--seed 8` and `--seed 9`. Which results change? What does that tell you about random initialization?

## Reproducibility and limitations

This example depends only on NumPy, uses fixed random seeds and no external dataset. There is no independent test set beyond the validation holdout, and no hyperparameter-search protocol: validation numbers should not be treated as unbiased final performance when used to select settings. The spiral construction is deterministic in structure, and its label rule is intentionally simple.
